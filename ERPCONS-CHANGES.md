# ERPCons changes

This branch (`erpcons`) is the ERPCons Văn phòng fork of [WordCraft](https://github.com/storytold/wordcraft), based on WordCraft by the ArtCraft team, licensed MIT OR Apache-2.0 (see `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`). Changes from upstream `main` (Apache-2.0 §4b):

- Removed the ArtCraft logos and marks (`docs/brand/`) and every link to the ArtCraft Discord and getartcraft.com, as the ArtCraft brand terms require for forks: About dialog, title-bar Discord button and its Options switch, Backstage and ribbon Discord entries, the `ui.discord` command, README.
- About now reads "ERPCons Văn phòng — dựa trên WordCraft của nhóm ArtCraft. MIT OR Apache-2.0." and links this fork's source.
- Sample document, LaTeX export header and MCP server info point at this fork or office.erpcons.vn instead of getartcraft.com.
- Dropped the translations of the removed strings and the word "artcraft" from the extra spelling list.
- Vietnamese Telex/VNI (and other input methods that rewrite what they typed) no longer garble text on the web: the canvas handles the browser's `DeleteSurrounding` IME event, deleting the taken-back characters around the caret (within its paragraph) together with the replacement in one Typing undo step. `text.insert` and `equation.type` take optional `deleteBefore` / `deleteAfter` counts for this.
- Web "Save changes?" → Save no longer loses the document when the browser's save picker is cancelled: `Services::download` reports a picker save as `Download::Pending`, the held-back New/Open/Close runs only once the file is written, and a cancelled or failed picker save marks the document it saved (not whichever is open) unsaved again. Anchor downloads (browsers without the picker) behave as before.
- Web draft autosave for the ERPCons office shell (`window.erpDrafts`): an unsaved document (dirty, or its picker save still pending) is put as DOCX — encrypted when it has a password, without stamping a save — after a 2.5 s pause, at least every 30 s of continuous editing, never more often than 10× its last serialization time and never mid-IME-composition, and at once when the tab is hidden or left (`visibilitychange`/`pagehide`). Its draft is removed once it is saved or closed. Drafts the shell restores open with no "Save changes?" prompt, unsaved, under their own name and key. Off when `erpDrafts` is absent or with `?host=parent`; the shell owns all text. Planner in `crates/ui-egui/src/drafts.rs`, app side in `draft_bridge.rs`, JS bridge in `apps/wordcraft-web/src/web/drafts.rs`.
- Vietnamese interface (`crates/ui-egui/src/i18n/vi.tsv`, code `vi`): every catalog key, tab and command translated clean-room, with Office-style Vietnamese tab, group and command names (feature names only). The web build opens in Vietnamese unless the user picked another language and remembers the choice in `localStorage` key `erpcons-ui-language`, which the other ERPCons editors share (`apps/wordcraft-web/src/web/language.rs`).
- F1 opens Keyboard Shortcuts (Phím tắt): every key combination in effect, custom keys from Customize Keyboard included, with its command's label in the interface language, searchable by label (translated or English) or by key (`Ctrl+Shift+S`). The list is built from the same key dispatch the editor runs, so it only shows keys that really run their command. Esc or Close closes it.
- Several documents open at once, each in its own tab under the title bar (shown from two documents up; a long title is cut with "…" and shown whole in its tooltip; a dot marks unsaved changes; × or a middle-click closes, through "Save changes?" naming that document). New, Open, a dropped file, a file opened from the shell and a restored draft open beside the open documents instead of replacing them (an untouched blank start document is still replaced), up to 10 documents. Each tab keeps its own undo history, selection, zoom, scroll, Find and panes; the clipboard, settings and AutoSave choice stay the user's. Every unsaved document is drafted under its own key, and restoring several drafts opens a tab for each. Closing the window asks about each unsaved document in turn. Store in `crates/ui-egui/src/open_documents.rs`, tab strip in `doc_tabs.rs`.
- Zip packages from outside (DOCX/DOCM/DOTX/DOTM, also inside an encrypted document; ODT; spreadsheets read as recipient lists) inflate through one bounded reader, `wordcraft_doc::inflate`, which checks what actually inflates rather than what the headers declare: an entry inflating more than 200:1 once past 4 MiB, an entry or a package over its cap (already when a header declares it), or too many entries refuses the whole file, even when the part was optional, and the status bar says "The file is too large or abnormally compressed, so it can't be opened." ("Tệp quá lớn hoặc bị nén bất thường nên không mở được."), leaving the File tab so it shows; with no document open (the web build's Start screen) the empty window's status bar keeps saying it. Desktop keeps 256 MiB per entry, 512 MiB per package and 20,000 entries; the web build allows 128 MiB and 256 MiB, since every part stays inflated while the document is open. Buffers grow with `try_reserve`, so a failed allocation is that error rather than a crashed tab.
- `deny.toml`: a cargo-deny policy matching PdfCraft's (permissive licences only, crates.io plus the pinned craft-libs revision as the only sources, no wildcard requirements, RustSec advisories with a written reason for each ignore). Run with `cargo deny check`.
- Phones and tablets (`NARROW_WIDTH` = 600 points of window width, `crates/ui-egui/src/narrow.rs`): crossing below it folds the ribbon once (expanding it by hand sticks until the width crosses back; a wide window gets the user's own wide choice back, which stays the saved `ribbonCollapsed`). A folded ribbon shows a clicked tab's commands over the page until a command runs, a click lands outside, Esc or the same tab again, as Word does (wide windows too). The tab strip scrolls sideways (finger drag on touch screens, edge chevrons) instead of clipping; narrow, Share, Editing and Comments sit behind a "⋯" menu. Side panes float over the page instead of squeezing it. The page fits the width (View › Page Width) with both rulers hidden, once per document per narrow spell (documents opened while narrow inherit the shown view); a zoom (pinch, +/−, slider) or ruler the user then picks stands, and widening gives every open document its wide zoom, fit mode and ruler back. None of this is saved in `ui.json`. The title bar drops AutoSave, shows search as an icon and cuts the title with "…"; the status bar keeps page, words, zoom and views (no slider, language or Focus) and clips rather than overlaps. On the page (`touch.rs`), touch only: a one-finger drag scrolls (and keeps the selection from before the press), a tap places the caret (the duplicate press/release browsers send for one touch is dropped, so a tap isn't a double-click), a long press selects the word and opens the context menu, two fingers still zoom, and in Read Mode a sideways swipe turns a column. Mouse and pen are unchanged.
- Fling on the page (touch only, `crates/ui-egui/src/fling.rs`): a quick one-finger page drag keeps scrolling after the finger lifts, slowing to a stop (GridCraft's model and constants: a release at 250 points/s or more starts it, it decays exponentially at a rate of 4/s and stops below 20 points/s); a slow release doesn't fling, an axis stops at the document's edge, and any press (a new touch catches the page), the wheel, middle-click scrolling or a jump to the caret stops it. Not after a pinch, not with animation effects off, and not in Read Mode, where the sideways swipe still turns a column. Mouse and pen are unchanged.
