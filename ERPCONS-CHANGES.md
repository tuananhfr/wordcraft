# ERPCons changes

## 2026-10-30: PI ID against the real PI Platform (`erpcons-account` v0.4.2)

- PI ID account (desktop): `erpcons-account` and the `pi-mock` dev-dependency move from v0.1.1 to v0.4.2, which talk to the real PI Platform (its ADR 0011/0012: `/api/v1/id/*` paths, PI's error envelope, organization switch with `org_hint`, `prompt=login` after sign-out). Office keeps `Config::offline_licensing` off (the library default), so no device, lease or entitlement endpoint is called and the licence reads as Free; the new `LicenceState::NotEntitled` (licensing only) also reads as Free. Switching organization now runs PI's browser authorization again and blocks until the browser returns, so File › Account shows the sign-in wait ("Continue in your browser…" with Cancel) while it runs, on the account worker thread; Cancel keeps the current organization and shows no error, and a context PI did not grant shows the existing "This organization is not available to your account." No new strings. The worker now publishes that wait itself when the flow starts, so a background reload cannot hide Cancel. Web build unchanged (the office shell does PI sign-in). Tests: the pi-mock sign-in test follows v0.4.2 (licence Free, only `/api/v1/id/me` under `/api/`), new `cancel_unblocks_an_organization_switch_waiting_for_the_browser` (`apps/wordcraft/src/account.rs`, `account/tests.rs`). Account tests 7/7; full gate (rustfmt, clippy, workspace tests, wasm32 clippy) passed, 2431 passed, 0 failed.

- Online documents v2, access modes (web, `window.erpHost` version 1 or 2, contract `erp-host.md` in erpcons-office): with `version === 2`, `open(doc)` also reads `mode` (`edit`, `comment`, `view`; absent is `edit`, any other value is `view`), `canDownload` (absent is true, anything but a boolean is false) and `preserveView`, and `ready` also registers `setMode(docId, mode, canDownload)` and `setUser(user)`. In `view` and `comment` (`comment` is `view` for the content in this phase) nothing can change the document: `Session::run`, the engine's single entry point, refuses every mutating command plus Undo, Redo, Edit Header/Footer, Encrypt and Save through the session's `Access` (it belongs to the session, so it is never written into the file and is not `w:documentProtection`), and the interface refuses what never reaches the engine: interface commands that edit (Change Picture, Link Text Box, recipient lists, Zotero), typed text and the input method (no IME request either, so phones keep their keyboard down), paste, cut, files dropped on the page (reported to `erpIntakeResult` as not opened), comment editing in balloons and the Comments pane, spelling suggestions and synonyms. Nor does the interface offer what it would refuse: dialogs whose OK edits the document don't open (only Find without its Replace tab, Go To, Word Count, Zoom, Help, the command and shortcut lists, the ribbon and keyboard customizing and the save and open prompts do; one already open when `setMode` turns editing off closes), objects get no handles and no move or resize drag, table borders, the table move handle and insert buttons, ruler markers and margins start no drag, and pens, the eraser and the ink lasso can't be picked up (one in hand draws nothing, Draw Table too). A comment edit or reply typed in a balloon and not yet posted when editing turns off is put aside, neither posted nor dropped, and comes back to its balloon when editing comes back to that document in this session; a draft in the Comments pane stays in its field, hidden while read-only, and that field gets the keyboard back. Refused commands are greyed out (ribbon buttons, split buttons such as Font Color and Highlight with their menus, the Styles, style set, pen and WordArt galleries, the context menu, Undo/Redo; the Navigation and Comments panes stay as they are) and say "Tài liệu này chỉ được xem, không sửa được." in the status bar, or in `comment` mode "Nhận xét trên web sẽ có sau, hiện chỉ xem được" (commenting stays view-only until M5; `Access::commenting`). A read-only page draws no caret (a click still places the selection), the tab strip's mode button says "Chỉ xem" ("Viewing") greyed with no menu, and the narrow window's "⋯" menu shows the same in place of the editing choices. With a version 2 host the shell's Share button is the only one: the tab strip's Share and the "⋯" menu's Share are hidden (`HostLink::set_shell_shares`).
 Navigation, selection, zoom, Find and view switches still work, and so do copy, Save As, Export, Print and Share unless `canDownload` is false, which refuses them ("Tài liệu này không cho phép tải xuống, in hay sao chép.") and drops anything egui would put on the clipboard. A read-only document has no AutoSave and Ctrl+S only says it is read-only; opened read-only it never becomes dirty and `flush` resolves at once. A downgrade first types any composition still in the input method into the document as one undo step, puts aside a balloon draft (above) and drops a queued AutoSave follow-up; a document downgraded with unsaved edits stays dirty and `flush` hands it to `save` (reason `flush`) until it is saved or stopped by a conflict or a non-retryable failure. `setMode` applies live both ways and keeps the content and the undo history. `preserveView` on a reload of an open document keeps the selection and the line at the top of the window where they still exist (a background tab keeps its selection only). `setUser({id, name})` makes `name` the author of new comments and tracked changes; `null` gives the preferences' name back, and the preferences never store the host's. Version 1 hosts and desktop are unchanged. Engine `crates/engine/src/access.rs`, app `crates/ui-egui/src/access_gate{,/dialogs}.rs` and `host_docs/{access,view_keep,draft_keep}.rs`, `ribbon_strip.rs`, page `apps/wordcraft-web/src/host/access.rs`.
- Online documents (web, `window.erpHost` v1, contract `erp-host.md` in erpcons-office): when the office shell defines `erpHost` with `version === 1` before the app starts, the app registers `ready({open, flush, acknowledged})` on its first frame. `open(doc)` opens a `.docx` beside the open documents under its title (a second `open` of the same `docId` reloads it in its tab, dropping local edits) and reports `opened(docId, ok, reason)` once, with no password prompt; `reason` is one of the shell's intake keys, never display text: `unsupported` for another format or a password-protected document (not online in v1), `parserFailed` for an unreadable file or the 10-document limit. Ctrl+S / Lưu on such a document calls `erpHost.save(docId, bytes, {revision, reason: 'manual'})` instead of the picker; AutoSave sends it 3 s after the last edit and at least every 30 s while edits keep coming; `flush()` hands every document with unacknowledged edits to `save` (reason `flush`, behind a save in flight) without waiting for a frame and resolves once each has been handed over, without waiting for the answers, or after 10 s. Documents stopped by a conflict or a non-retryable failure, and those whose save would drop something the user must confirm (a signature, macros), are neither autosaved nor flushed; Ctrl+S, which asks, still sends them. One save is in flight per document; triggers meanwhile coalesce into one follow-up of the newest revision. A document is clean only on `saved`, or on the shell's `acknowledged(docId, revision, version)` after its own retry of an offline or retryable save, and only as of that revision (an older acknowledgement, one for a revision never sent and an unknown `docId` are ignored); `conflict` stops AutoSave and leaves it dirty (never retried by itself), `offline` and retryable failures keep it dirty with AutoSave on and show nothing, a non-retryable failure stops AutoSave and shows the shell's message as a failed save (a later Ctrl+S that is saved, or an `acknowledged`, turns AutoSave back on). `dirty(docId, bool)` follows the revision against the acknowledged one; closing the tab calls `closed(docId)`; "Save changes?" › Save waits for the host's answer before closing. These documents are never put in `erpDrafts`, never offered by "Reopen closed document" and not counted by the app's leave-page guard (the shell guards them); Save As, Export, Print and Share still download a local copy and leave the document unsaved. Without `erpHost`, and on desktop, nothing changes. Save logic in `crates/ui-egui/src/host_docs/` (frame-independent so a hidden page's flush still goes out), JS bridge in `apps/wordcraft-web/src/host/`; the `log_privacy` check now also flags a logged `doc_id`.
- altChunk import (both): DOCX `altChunk`s holding HTML, XHTML, MHTML (`.mht` web archives, their pictures included), RTF or plain text become document content when the file opens, as Word imports them, so a document whose body is only such a chunk (ERP print forms) no longer opens blank. Their styles, lists and pictures are adopted as a paste is (pictures fitted to the text width), the file's sections stay, and saving writes the content instead of the chunk. Chunks of other types (DOCX) and ones that fail to convert stay preserved with the existing notice (`crates/formats/src/mhtml.rs`, `crates/engine/src/io/alt_chunk.rs`). Layout fidelity is the HTML importer's: it ignores cell widths, cell alignment and `text-transform`.
- File access V3, Share (web): when the office shell's `window.erpCanShareFiles(<DOCX MIME type>)` (asked once at start) says the browser can share a Word document (Safari; Chromium refuses Office types, so there Share keeps opening Export), the tab strip's Share (and the narrow window's "⋯" › Share) hands the document to the system share sheet through `window.erpShare(bytes, name, mime)` within the click instead of opening File › Export, and File gets a "Share…" ("Chia sẻ…") entry after Export. The bytes are those Save downloads (same name, .doc → .docx, still encrypted with the document's password); a loss warning comes first and both its Save anyway and Save a copy share; the shell declining downloads the same copy; the document stays unsaved. Only a pointer click shares: Enter or Space on a focused Share (or loss-warning button) lands a frame later without user activation and downloads the copy instead. No shortcut. Downloads of .docm, .dotx and .dotm carry their own MIME types. Without the shell functions, and on desktop, nothing changes (`crates/ui-egui/src/share.rs`, `apps/wordcraft-web/src/web/share.rs`).
- File access V3, intake result (web): each file dropped on the page (the shell's ?open=, launch and share-target files arrive this way) is reported once to `window.erpIntakeResult(name, size, ok)` after the app decided: opened (a password prompt counts), picture inserted, recipients loaded or font added; or refused, unreadable, or past the 10-document limit. Files from the Open picker are not reported (`apps/wordcraft-web/src/intake.rs`).
- Logs name no documents (both): a document's name or path shows as its extension and size (`couldn't read a dropped .docx (12345 bytes)`), engine errors quoted in logs lose it too, and settings, font and log folders show the home folder as `~` (`wordcraft_fonts::log_safe`). The xtask test `log_privacy` fails on a log record in `apps/`, `crates/ui-egui`, `crates/engine` or `crates/fonts` that interpolates a name, path or URL outside its allowlist, or an error logged within ten lines of a document open or save without `log_safe::scrub`.

- Removed the ArtCraft logos and marks (`docs/brand/`) and every link to the ArtCraft Discord and getartcraft.com, as the ArtCraft brand terms require for forks: About dialog, title-bar Discord button and its Options switch, Backstage and ribbon Discord entries, the `ui.discord` command, README.
- About now reads "ERPCons Văn phòng — dựa trên WordCraft của nhóm ArtCraft. MIT OR Apache-2.0." and links this fork's source.
- Sample document, LaTeX export header and MCP server info point at this fork or office.erpcons.vn instead of getartcraft.com.
- Dropped the translations of the removed strings and the word "artcraft" from the extra spelling list.
- Vietnamese Telex/VNI (and other input methods that rewrite what they typed) no longer garble text on the web: the canvas handles the browser's `DeleteSurrounding` IME event, deleting the taken-back characters around the caret (within its paragraph) together with the replacement in one Typing undo step. `text.insert` and `equation.type` take optional `deleteBefore` / `deleteAfter` counts for this.
- Web "Save changes?" → Save no longer loses the document when the browser's save picker is cancelled: `Services::download` reports a picker save as `Download::Pending`, the held-back New/Open/Close runs only once the file is written, and a cancelled or failed picker save marks the document it saved (not whichever is open) unsaved again. Anchor downloads (browsers without the picker) behave as before.
- Web draft autosave for the ERPCons office shell (`window.erpDrafts`): an unsaved document (dirty, or its picker save still pending) is put as DOCX — encrypted when it has a password, without stamping a save — after a 2.5 s pause, at least every 30 s of continuous editing, never more often than 10× its last serialization time and never mid-IME-composition, and at once when the tab is hidden or left (`visibilitychange`/`pagehide`). Its draft is removed once it is saved or closed. Drafts the shell restores open with no "Save changes?" prompt, unsaved, under their own name and key. Off when `erpDrafts` is absent or with `?host=parent`; the shell owns all text. Planner in `crates/ui-egui/src/drafts.rs`, app side in `draft_bridge.rs`, JS bridge in `apps/wordcraft-web/src/web/drafts.rs`.
- Vietnamese interface (`crates/ui-egui/src/i18n/vi.tsv`, code `vi`): every catalog key, tab and command translated clean-room, with Office-style Vietnamese tab, group and command names (feature names only). The web build opens in Vietnamese unless the user picked another language and remembers the choice in `localStorage` key `erpcons-ui-language`, which the other ERPCons editors share (`apps/wordcraft-web/src/web/language.rs`).
- F1 opens Keyboard Shortcuts (Phím tắt): every key combination in effect, custom keys from Customize Keyboard included, with its command's label in the interface language, searchable by label (translated or English) or by key (`Ctrl+Shift+S`). The list is built from the same key dispatch the editor runs, so it only shows keys that really run their command. Esc or Close closes it.
- Several documents open at once, each in its own tab under the title bar (shown from two documents up; a long title is cut with "…" and shown whole in its tooltip; a dot marks unsaved changes; × or a middle-click closes, through "Save changes?" naming that document). New, Open, a dropped file, a file opened from the shell and a restored draft open beside the open documents instead of replacing them (an untouched blank start document is still replaced), up to 10 documents. Each tab keeps its own undo history, selection, zoom, scroll, Find and panes; the clipboard, settings and AutoSave choice stay the user's. Every unsaved document is drafted under its own key, and restoring several drafts opens a tab for each. Closing the window asks once about every unsaved document (see below). Store in `crates/ui-egui/src/open_documents.rs`, tab strip in `doc_tabs.rs`.
- Zip packages from outside (DOCX/DOCM/DOTX/DOTM, also inside an encrypted document; ODT; spreadsheets read as recipient lists) inflate through one bounded reader, `wordcraft_doc::inflate`, which checks what actually inflates rather than what the headers declare: an entry inflating more than 200:1 once past 4 MiB, an entry or a package over its cap (already when a header declares it), or too many entries refuses the whole file, even when the part was optional, and the status bar says "The file is too large or abnormally compressed, so it can't be opened." ("Tệp quá lớn hoặc bị nén bất thường nên không mở được."), leaving the File tab so it shows; with no document open (the web build's Start screen) the empty window's status bar keeps saying it. Desktop keeps 256 MiB per entry, 512 MiB per package and 20,000 entries; the web build allows 128 MiB and 256 MiB, since every part stays inflated while the document is open. Buffers grow with `try_reserve`, so a failed allocation is that error rather than a crashed tab.
- `deny.toml`: a cargo-deny policy matching PdfCraft's (permissive licences only, crates.io plus the pinned craft-libs revision as the only sources, no wildcard requirements, RustSec advisories with a written reason for each ignore). Run with `cargo deny check`.
- Phones and tablets (`NARROW_WIDTH` = 600 points of window width, `crates/ui-egui/src/narrow.rs`): crossing below it folds the ribbon once (expanding it by hand sticks until the width crosses back; a wide window gets the user's own wide choice back, which stays the saved `ribbonCollapsed`). A folded ribbon shows a clicked tab's commands over the page until a command runs, a click lands outside, Esc or the same tab again, as Word does (wide windows too). The tab strip scrolls sideways (finger drag on touch screens, edge chevrons) instead of clipping; narrow, Share, Editing and Comments sit behind a "⋯" menu. Side panes float over the page instead of squeezing it. The page fits the width (View › Page Width) with both rulers hidden, once per document per narrow spell (documents opened while narrow inherit the shown view); a zoom (pinch, +/−, slider) or ruler the user then picks stands, and widening gives every open document its wide zoom, fit mode and ruler back. None of this is saved in `ui.json`. The title bar drops AutoSave, shows search as an icon and cuts the title with "…"; the status bar keeps page, words, zoom and views (no slider, language or Focus) and clips rather than overlaps. On the page (`touch.rs`), touch only: a one-finger drag scrolls (and keeps the selection from before the press), a tap places the caret (the duplicate press/release browsers send for one touch is dropped, so a tap isn't a double-click), a long press selects the word and opens the context menu, two fingers still zoom, and in Read Mode a sideways swipe turns a column. Mouse and pen are unchanged.
- Fling on the page (touch only, `crates/ui-egui/src/fling.rs`): a quick one-finger page drag keeps scrolling after the finger lifts, slowing to a stop (GridCraft's model and constants: a release at 250 points/s or more starts it, it decays exponentially at a rate of 4/s and stops below 20 points/s); a slow release doesn't fling, an axis stops at the document's edge, and any press (a new touch catches the page), the wheel, middle-click scrolling or a jump to the caret stops it. Not after a pinch, not with animation effects off, and not in Read Mode, where the sideways swipe still turns a column. Mouse and pen are unchanged.
- Reopen, close several, save status (`closed_documents.rs`, `close_many.rs`, `save_status.rs`): the last 10 documents closed in this session (64 MB of bytes at most, oldest dropped first) are kept as their draft bytes would be, encrypted when the document has a password (reopening asks for it), with their name and unsaved state; Reopen Closed Document ("Mở lại tài liệu vừa đóng": File › Open; a document tab's context menu; no shortcut, so Ctrl+Shift+T stays Reduce Hanging Indent) opens the last one beside the others, unsaved if it was, within the 10-documents limit. A tab's context menu also has Close, Close Others and Close All ("Đóng các tài liệu khác", "Đóng tất cả"). Closing several documents (those, or the window) asks once, naming every unsaved one, Save All / Don't Save / Cancel (one unsaved document gets the usual "Save changes?"); Save All saves them one after another, each save finished before the next starts; in the browser each save picker needs a click of its own, so once one has written its file the question stays up, marks that row "— Đã lưu" ("— Đang lưu…" while it writes) and its button becomes "Lưu “<next name>”" for the next. Browsers without the picker download them all at once; desktop goes through Save As without stopping. A cancelled or failed save stops the rest and closes nothing still unsaved. The status bar shows "Đang lưu…" while the browser's save picker writes the shown document, and "Lưu không thành công" (the reason in its tooltip, or a tap) after a failed save, AutoSave included, until the document is saved or edited (narrow, it goes before the page count in place of the word count, so it is never cut); desktop writes within one frame, so only its failures show.

- Clipboard command keys are filtered before egui input to avoid running Copy, Cut and Paste twice; Paste Special uses the paste event, while Shift formatting and other Alt shortcuts are preserved (web only).
- Rich clipboard bridge preserves available HTML/RTF, pastes image-only clipboards, reads menu Paste asynchronously, and reports browser clipboard failures; rich data expires after its paste frame (web only).
- Copy and Cut always export selection HTML with a bounded internal fragment marker; cross-document paste adopts styles, numbering and media in one undo step, preserves destination style rules unless Keep Source is requested, and translates clipboard failures into Vietnamese (both).

- Close document button: show the existing close icon below the compact breakpoint, including at 390 px, using the normal unsaved-changes flow (both).
- Focus mode: hide editor chrome and rulers, preserve typing and Escape priority, and show a one-time translated exit hint (both).
- Closed hook: finish the browser's last-document close and call the optional window.erpEditorClosed callback once, after no document remains (web).

- Desktop recovery keeps bounded, atomically replaced DOCX drafts for unsaved work in per-instance directories with Windows-safe sibling lock files, recovers only exited instances, restores them as clearly marked unsaved documents on startup, and removes them after save, discard or approved shutdown (desktop).
- Native file filters, clipboard errors, default-app messages and print queue document labels use the interface catalog, with Vietnamese translations (desktop).

- Undo/Redo now share protection-aware availability, expose transaction IDs and timestamps, keep nested commands in one transaction, and provide accessible disabled controls with 44-point narrow-layout targets; save and draft history is regression-tested.
